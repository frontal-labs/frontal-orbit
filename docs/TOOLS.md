# Developer Tools Reference

This document is the canonical reference for frontal-orbit's repo-level
developer tooling, located under [`tools/`](../tools). These tools are
**infrastructure for developing and operating the monorepo** — they are not part
of the `orbit` agent binary, and they are distinct from `crates/tools/` (the
agent's runtime tool system).

- **Canonical code:** `tools/<name>/`
- **Delegators:** `scripts/<name>.sh` → `tools/`
- **Make targets:** `make <name>` (see [`Makefile`](../Makefile))
- **Config:** `.orbit.json` → `devtools` (machine-readable index)
- **Bazel:** `//tools/<name>:<name>` (an `sh_binary` wrapping `//tools:cargo_run.sh`)

> **Bazel note.** The Rust tools build via `cargo` and are wrapped by Bazel
> `sh_binary` targets (`//tools:cargo_run.sh`). This keeps `bazel build //...`
> hermetic and green without `rules_rust`. The migration to native `rust_binary`
> is tracked in [`docs/bazel/ROADMAP.md`](./bazel/ROADMAP.md).

## doctor

Environment and toolchain health checker. Verifies the toolchains the monorepo
depends on, validates `.orbit.json`, and optionally probes network egress.
Exits non-zero if any required check fails, so it can gate CI.

- **Kind:** Rust · **Package:** `tools-doctor` · **Bazel:** `//tools/doctor:doctor` · **Make:** `make doctor`
- **Commands / flags:**
  - `--format text|json` — human table or machine-readable JSON (default `text`)
  - `--check-network` — also probe outbound connectivity to `static.crates.io`
  - `--root <dir>` — directory to inspect (default `.`)
- **Example:**
  ```bash
  cargo run -q -p tools-doctor -- --root .
  cargo run -q -p tools-doctor -- --format json --check-network
  ```
- **Checks:** `bazel` (vs `.bazelversion` pin), `rustc`, `cargo`, `node`,
  `docker`, `git`, `pre-commit`, `.orbit.json` validity, `Cargo.lock` presence.
- **Output:** text table with `[ok]`/`[FAIL]` per check, plus a trailing
  `N checks, M failing` line; JSON form emits `{"checks":[…],"failed":M}`.
- **CI:** surfaced by the existing `orbit-doctor` pre-commit hook and runnable
  as `bazel test //bazel/ci:third_party_check` siblings.

## coverage

Runs `bazel coverage //...` and aggregates the resulting `lcov` report.

- **Kind:** Mixed · **Package:** `tools-coverage` · **Bazel:** `//tools/coverage:coverage` (shell) and `//tools/coverage:tools-coverage` (aggregator) · **Make:** `make coverage`
- **Canonical entry:** `tools/coverage/coverage.sh` (delegated by `scripts/coverage.sh`). It runs `bazel coverage //...`, locates the produced `lcov.info`, and pipes it to the Rust aggregator.
- **Aggregator commands:**
  - `summarize <path> [--format text|json]` — parse an lcov file and report per-file and total line coverage.
- **Example:**
  ```bash
  make coverage                 # full run
  cargo run -q -p tools-coverage -- summarize coverage/lcov.info
  ```
- **Inputs:** `lcov.info` (generated by `bazel coverage`).
- **Output:** per-file `%` lines and a `TOTAL` summary; JSON form emits
  `{files:[{file,found,hit,percent}],total_found,total_hit,total_percent}`.
- **Notes:** Requires network/Bazel modules to produce the report; the
  aggregator itself is offline-safe.

## benchmark

Lightweight build / CI timing harness. Useful for tracking build-time and CLI
latency regressions.

- **Kind:** Rust · **Package:** `tools-benchmark` · **Bazel:** `//tools/benchmark:benchmark` · **Make:** `make bench`
- **Commands:**
  - `build` — time `cargo build --workspace`
  - `sizes` — list built binaries under `target/debug` with sizes
  - `run <command> [args…]` — time an arbitrary command
  - `--format text|json` (default `text`)
- **Example:**
  ```bash
  cargo run -q -p tools-benchmark -- build
  cargo run -q -p tools-benchmark -- run cargo --version
  ```
- **Output:** `kind  elapsed_ms  (detail)`; JSON form emits
  `{kind,elapsed_ms,detail}`. Diff against a baseline to spot regressions.

## cache

Inspect and prune build caches (Bazel output base + Cargo `target/`).

- **Kind:** Rust · **Package:** `tools-cache` · **Bazel:** `//tools/cache:cache` · **Make:** `make cache`
- **Commands:**
  - `status` — report Bazel output-base and Cargo `target/` sizes (human-readable)
  - `clean [--expunge]` — run `bazel clean` (optionally `--expunge`)
  - `prune --yes` — remove `target/` (refuses without `--yes`)
- **Example:**
  ```bash
  cargo run -q -p tools-cache -- status
  cargo run -q -p tools-cache -- prune --yes
  ```
- **Output:** sizes printed to stdout; mutating commands report success/failure.

## codegen

Generate Rust boilerplate from names or JSON schemas.

- **Kind:** Rust · **Package:** `tools-codegen` · **Bazel:** `//tools/codegen:codegen` · **Make:** `make codegen`
- **Commands:**
  - `command <Name>` — emit a clap-derived command module skeleton (`Args` struct + `run`)
  - `struct <Name> --from <file.json>` — emit a `serde` struct inferred from a JSON sample (types: bool/i64/f64/String/Vec/…)
  - `--out <file>` — write to a file instead of stdout
- **Example:**
  ```bash
  cargo run -q -p tools-codegen -- command Deploy > crates/cli/src/commands/deploy.rs
  cargo run -q -p tools-codegen -- struct Config --from config.sample.json
  ```
- **Output:** Rust source on stdout or `--out`.

## fuzz

Discover, scaffold, and run fuzz targets.

- **Kind:** Rust (runner) · **Package:** `tools-fuzz` · **Bazel:** `//tools/fuzz:fuzz` · **Make:** `make fuzz`
- **How it works:** fuzz targets live under `tools/fuzz/fuzz_targets/<name>/` as
  standalone `cargo-fuzz` crates. They are **excluded from the main workspace**
  (`exclude = ["tools/fuzz/fuzz_targets/*"]` in the root `Cargo.toml`) so they
  never perturb `cargo build --workspace`.
- **Commands:**
  - `list` — list discovered targets
  - `new <name>` — scaffold a target from `tools/templates/templates/fuzz/`
  - `run <name> [extra args…]` — dispatch to `cargo +nightly fuzz run <name>`
- **Example:**
  ```bash
  cargo run -q -p tools-fuzz -- list
  cargo run -q -p tools-fuzz -- new parse_smoke
  cargo +nightly fuzz run parse_smoke
  ```
- **Requirements:** `cargo-fuzz` + nightly toolchain to actually run targets.
- **Sample target:** `tools/fuzz/fuzz_targets/parse_smoke/` exercises UTF-8/JSON
  parsing paths; replace the body with a real parser under test.

## generators

Scaffold new crates from templates (consumes `tools-templates`).

- **Kind:** Rust · **Package:** `tools-generators` · **Bazel:** `//tools/generators:generators` · **Make:** `make generators`
- **Commands:**
  - `crate <name> [--kind lib|bin] [--dest <dir>]` — generate a crate under `<dest>` (default `crates/`)
- **Example:**
  ```bash
  cargo run -q -p tools-generators -- crate my_feature --kind lib
  ```
- **Templates:** `tools/templates/templates/crate/{Cargo.toml,crate_lib.rs,crate_bin.rs}`
  (rendered with the shared `{name}` substitution).
- **Output:** writes `Cargo.toml` + `src/lib.rs` or `src/main.rs`; reminds you to
  build and (if needed) register the new member.

## remote

Generate and validate Bazel remote-cache / RBE configuration.

- **Kind:** Rust · **Package:** `tools-remote` · **Bazel:** `//tools/remote:remote` · **Make:** `make remote`
- **Commands:**
  - `init --endpoint <grpcs://…>` — write a remote-cache snippet to `.bazelrc.project`
  - `show` — print the current remote config (if any)
  - `check` — read the configured `build --remote_cache=` endpoint
- **Example:**
  ```bash
  cargo run -q -p tools-remote -- init --endpoint grpcs://remote-cache.example.com
  cargo run -q -p tools-remote -- check
  ```
- **Notes:** `.bazelrc.project` is gitignored machine-local config (see
  `docs/bazel/GETTING-STARTED.md`). Pick a backend (GCS/S3/gRPC RBE) when wiring
  CI — tracked as an open question in the implementation plan.

## telemetry

Wrap a build/CI command and emit a telemetry event.

- **Kind:** Rust · **Package:** `tools-telemetry` · **Bazel:** `//tools/telemetry:telemetry` · **Make:** `make telemetry`
- **Commands:**
  - `wrap <name> <command> [args…]` — run a command, time it, emit an event
  - `event <name> [--level info|error] [--message …]` — emit a standalone event
  - `--config <file>` — `.orbit.json` path for telemetry config (default `.orbit.json`)
- **Example:**
  ```bash
  cargo run -q -p tools-telemetry -- wrap ci_build cargo build --workspace
  cargo run -q -p tools-telemetry -- event deploy --message "released v0.2.0"
  ```
- **Destination:** reads the `telemetry` block of `.orbit.json`; if telemetry is
  disabled or the file is absent, events print to stdout. When enabled, events
  append as JSONL to `telemetry.path`.
- **Output:** JSON event `{ts,name,level,message,duration_ms,exit_ok}`.

## templates

Shared templating library. **No CLI** — it is consumed by `generators` and
`codegen`.

- **Kind:** Lib · **Package:** `tools-templates` · **Bazel:** exported files under `//tools/templates`
- **API:** `render(template, &HashMap<&str,String>)` substitutes `{key}`
  occurrences; unknown placeholders are left intact; `{{`/`}}` are literal braces.
  `render_file(dir, name, vars)` loads and renders a template file.
- **Templates shipped:**
  - `templates/crate/{Cargo.toml,crate_lib.rs,crate_bin.rs}` — used by `generators`
  - `templates/fuzz/{Cargo.toml,target.rs}` — used by `tools-fuzz new`
- **Tests:** unit tests cover substitution, unknown-var passthrough, and brace escaping.

## version

Bump the monorepo version across the root files.

- **Kind:** Rust · **Package:** `tools-version` · **Bazel:** `//tools/version:version` · **Make:** `make version`
- **Commands:**
  - `show` — print the current version
  - `bump <major|minor|patch>` — increment a part
  - `set <X.Y.Z>` — set an explicit version
  - `--dry-run` — print the would-be writes without mutating (global flag)
  - `--manifest <file>` / `--module <file>` — override targets (global flags)
- **Example:**
  ```bash
  cargo run -q -p tools-version -- show
  cargo run -q -p tools-version -- bump patch --dry-run
  cargo run -q -p tools-version -- bump minor
  ```
- **Files touched:** `[workspace.package].version` in `Cargo.toml` (crates that
  use `version.workspace = true` inherit automatically) and `module(version=…)`
  in `MODULE.bazel`. Optionally stamps `## [version] - unreleased` into
  `CHANGELOG.md` when not in dry-run.
- **Pre-commit:** `devtools-version-sync` asserts `Cargo.toml` and `MODULE.bazel`
  versions stay in lockstep.

## workspace

Validate and maintain the Cargo workspace member list.

- **Kind:** Rust · **Package:** `tools-workspace` · **Bazel:** `//tools/workspace:workspace` · **Make:** `make workspace`
- **Commands:**
  - `list` — print members
  - `check` — verify every member exists and scan for duplicate dependency names
  - `sort` — rewrite the member list in sorted order (in place)
  - `--manifest <file>` — override target (global flag)
- **Example:**
  ```bash
  cargo run -q -p tools-workspace -- list
  cargo run -q -p tools-workspace -- check
  cargo run -q -p tools-workspace -- sort
  ```
- **Pre-commit:** `devtools-workspace-check` runs `check` whenever a `Cargo.toml`
  changes, guarding against missing members and duplicate deps.

## Cross-tool dependencies

```
templates ──► generators, codegen, fuzz (template source)
workspace ──► (CI gate) validates members after generators adds crates
version   ──► (CI gate) keeps Cargo.toml ↔ MODULE.bazel in sync
coverage  ──► wraps `bazel coverage` then feeds tools-coverage
remote    ──► writes .bazelrc.project consumed by `bazel` invocations
telemetry ──► wraps any command (e.g. benchmark, coverage) to record runs
```

## CI integration

- `bazel/ci/tools_smoke.sh` (tagged `manual`) runs lightweight invocations of
  every tool; invoke it via `bazel test //bazel/ci:tools_smoke` in CI.
- Pre-commit hooks `devtools-workspace-check` and `devtools-version-sync` guard
  workspace/version integrity on commit.
